# Local Lessons Learned

- [Initial Setup]: Hub initialized with basic autonomous agent and workflows.
- [2026-08-05]: Discovered the autonomous agent never fetched real code from spoke repos - it only read lessons.md/NORTH_STAR.md and then asked an LLM to audit "the latest code" with none actually in the prompt. This produced ~2,000 hallucinated GitHub issues in one spoke (tso) over ~4 months. Fixed by fetching the spoke's latest commit diff and including it in the prompt, and by skipping the AI call entirely when there's no usable diff.
- [2026-08-05]: The AI's JSON response was trusted blindly - a parse failure fabricated a synthetic result and posted an issue anyway, and a successful-but-wrong-shaped response got string-interpolated straight into the issue body (producing literal "undefined" / "[object Object]"). Fixed by validating the response shape before ever calling `issues.create`, and skipping (not fabricating) on any failure.
- [2026-08-06]: Fixing the hallucination root cause wasn't enough on its own to trust re-enabling automation - a bug in a future prompt/model change could still refile the same mistake at scale before anyone noticed. Added two independent safety rails on top of the validation fix: a `DRY_RUN_MODE` env var (default on) that reports findings without ever filing them, and a hard `RATE_CAP_PER_REPO_PER_DAY` (default 3) once dry-run is off. Both fail safe - a missing/misconfigured env var means no issue gets filed, not the reverse.
- [2026-08-06]: `ai_decision_log.json` was part of the spoke setup contract from the start but nothing ever read or wrote it - real decision logging is now live. Every decision (skip, dry-run finding, rate-capped, created) gets appended with its commit sha, so the same commit+mode combination is never re-analyzed by the AI twice, and the last few decisions get fed back into the prompt so the model has memory of what it already decided instead of re-litigating it every run.
- [2026-08-06]: The "Recursive Learning Loop" the README described was aspirational - nothing aggregated insights across spokes automatically. Built `api/recursive_learning.js`: a monthly job that reads every spoke registered in `spokes.json`, looks for a pattern that recurs across more than one of them, and - if it finds one - opens a PR against this repo proposing an update to `universal_lessons.md`/`north_star_framework.md`. It never pushes directly to `main`; a human still reviews and merges. Seeded `spokes.json` with `tso`, the one spoke actually connected today.
- [2026-08-06]: `scripts/prune-logs.js` had been a no-op stub since the hub's first setup - "Pruner initialized..." and nothing else, never invoked by any workflow. Replaced with a real implementation: for every spoke in `spokes.json`, archive `ai_decision_log.json` entries older than a retention window into `ai_decision_log_archive.json` (archive written before the live log is truncated, so a mid-run failure can't lose data), then wired it into a weekly Sunday workflow. Runs as a plain Actions script, not a Vercel function - no AI involved, so it only needs a GitHub token, not the AI credentials.
